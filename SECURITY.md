# Security Policy — Jarvis Lite

## Модель безопасности

Jarvis Lite построен на принципе **минимальных привилегий и явного белого списка**.  
Каждое действие требует явной авторизации на нескольких уровнях.

---

## Whitelist-модель

### Пользователи (ALLOWED_USER_IDS)

Бот отвечает **только** пользователям, чьи Telegram user ID перечислены  
в переменной `ALLOWED_USER_IDS`. Любое сообщение от неизвестного пользователя  
получает ответ `Access denied` и фиксируется в audit-log со статусом `rejected`.

Telegram user ID — числовой идентификатор, который нельзя подделать через username.

### Контейнеры (SAFE_CONTAINERS)

Любая команда, работающая с Docker-контейнерами (`/logs`, `/errors`,  
`/analyze_logs`, `/restart`, callback-кнопки), **проверяет имя контейнера**  
по списку `SAFE_CONTAINERS` перед выполнением.

Если контейнер не в whitelist — команда отклоняется, действие не выполняется.

Это исключает возможность управлять системными или неизвестными контейнерами  
даже при компрометации авторизованного Telegram-аккаунта.

## Почему нет /shell, /exec, /run

Команды `/shell`, `/exec`, `/run` **принципиально не реализованы**.

Произвольное выполнение shell-команд через Telegram означало бы:

- неограниченный доступ к серверу через единственный фактор (Telegram-аккаунт);
- возможность выполнить `rm -rf`, `curl | bash`, изменить конфигурацию;
- полный обход whitelist-модели.

Все системные вызовы в коде используют `subprocess.run(args_list, shell=False)`  
с заранее заданными аргументами. Пользовательский ввод **не попадает**  
в аргументы подпроцессов.

## Почему /restart требует /confirm

Перезапуск контейнера — деструктивная, но необратимая на короткий срок операция.  
Случайное нажатие кнопки или перехваченное сообщение не должны приводить к downtime.

Механизм подтверждения:

1. `/restart <container>` создаёт pending action с одноразовым кодом (8 hex символов).
2. Код действует **90 секунд**. После истечения действие автоматически удаляется.
3. Только `/confirm <code>` или кнопка **Confirm restart** от того же user ID  
   выполняет `docker restart`.
4. Каждый шаг логируется в audit-log.

Даже если злоумышленник получит доступ к Telegram-аккаунту на короткое время —  
у него будет максимум 90 секунд на подтверждение, и только для авторизованных контейнеров.

## Почему AI_PROVIDER=local — самый безопасный режим

Режим `local` означает, что логи **не покидают сервер**. Анализ выполняется  
локально с помощью набора правил (регулярные выражения + ключевые слова).

При использовании `openai` или `anthropic`:

- фрагменты логов отправляются на сторонний API;
- возможна утечка конфигурационных данных, путей, имён хостов;
- требуется хранение API-ключей в `.env`.

Перед отправкой в любой AI-провайдер логи проходят маскировку секретов  
(`TOKEN=`, `KEY=`, `PASSWORD=` → `[REDACTED]`), но это не даёт 100% гарантии.

**Рекомендация**: использовать `AI_PROVIDER=local` по умолчанию.  
Переключать на `openai`/`anthropic` только если локального анализа недостаточно  
и вы понимаете, что данные логов будут отправлены на внешний сервис.

## Как не слить .env и токены

### .gitignore

`.env` включён в `.gitignore`. Никогда не добавляйте его в git-индекс.

```bash
# Проверить, что .env не отслеживается
git ls-files .env  # должно быть пусто
```

### Права доступа

```bash
chmod 600 /opt/jarvis-lite/.env
chown jarvis:jarvis /opt/jarvis-lite/.env
```

### Systemd EnvironmentFile

Systemd читает `.env` через `EnvironmentFile=` и передаёт значения как переменные окружения.  
Файл доступен только пользователю `jarvis`.

### Ротация токена

Если токен бота скомпрометирован:

1. Перейдите к [@BotFather](https://t.me/BotFather) → `/revoke`.
2. Получите новый токен.
3. Обновите `TELEGRAM_BOT_TOKEN` в `.env`.
4. Перезапустите сервис: `systemctl restart jarvis-lite`.

### Audit log

`logs/audit.log` содержит только: timestamp, user_id, username, action, target, status.  
**Никогда** не содержит: токены, секреты, содержимое `.env`, полные логи контейнеров.

## Известные ограничения

- Нет 2FA для Telegram-аккаунта — если аккаунт авторизованного пользователя  
  скомпрометирован, атакующий получит доступ к боту. Включите 2FA в Telegram.
- Бот работает на сервере под пользователем `jarvis` с доступом к Docker.  
  Пользователь в группе `docker` фактически имеет root-доступ через Docker.  
  Это стандартное ограничение Docker-модели безопасности.
- `logs/audit.log` не защищён от удаления пользователем `jarvis`.  
  Для production рекомендуется отправлять audit-события в syslog или внешний SIEM.
